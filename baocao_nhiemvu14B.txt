2. Rà soát logic candidate

- Ownership: asset được truy vấn theo `owner_id=actor`; object phải có `owner_id=actor::text`, đúng bucket và đúng object path do asset xác định. Message finalize khóa conversation rồi khóa lại asset.
- MIME: chỉ nhận PNG/JPEG/WebP; MP4 chỉ cho post/message. MIME object phải khớp MIME asset và allowlist của bucket.
- Size: metadata size chỉ cast sang bigint khi là số dương có tối đa 12 chữ số; phải lớn hơn 0, không vượt trần 10 MiB cho profile hoặc 50 MiB cho social/chat, cũng không vượt `file_size_limit` live.
- Object existence: join object với bucket theo bucket ID và object name; thiếu object hoặc object ID bị null thì từ chối. Object ID được lưu lại ở metadata sau finalize.
- Idempotency: asset đã `ready` vẫn đi qua kiểm tra object ownership/metadata/private trước khi trả lại; trạng thái pending hết hạn bị từ chối. Không thể xác nhận các hành vi trên có khớp schema thật nếu chưa đọc Cloud.
- Private Storage: đã sửa điều kiện để chỉ chấp nhận bucket có `public = false`. Candidate không bật public, tắt RLS hoặc thay Storage policies.
- Hai hàm prepare dùng `started_at := transaction_timestamp()`; nếu helper trả về asset không có marker direct, chỉ nâng marker khi asset pending và `created_at = started_at`. `now()` là transaction timestamp nên phù hợp với default `created_at DEFAULT now()` trong schema local. Nhánh lookup ban đầu từ chối intent legacy đã tồn tại. Cần xác minh default/schema Cloud trước deploy.
- Quyền EXECUTE trong candidate: private helper mới bị revoke khỏi PUBLIC/anon/authenticated/service_role, rồi cấp cho authenticated để SQL SECURITY INVOKER wrapper hoạt động. Wrapper public bị revoke PUBLIC/anon và cấp authenticated. Finalize private chỉ cấp authenticated. Schema `private` không nên nằm trong exposed schemas của PostgREST; cần kiểm tra cấu hình/grants thật trên Cloud. Đây là review file, chưa chứng minh effective privilege live.
- Storage policies local được tham chiếu từ migrations cũ: INSERT giới hạn owner, intent/path hợp lệ và standard upload; policy restrictive yêu cầu `object.upload` cho ba bucket ứng dụng; SELECT yêu cầu authenticated read operation và `can_read_object`. Bucket social-media local khai báo private với allowlist PNG/JPEG/WebP/MP4, tối đa 50 MiB. Chưa xác nhận policy/bucket thật trên Cloud, đặc biệt `social-media`.

2. Mở SQL Editor, chạy truy vấn chỉ đọc dưới đây và đối chiếu kết quả với candidate cùng migrations nền. Dừng nếu thiếu signature/prerequisite, bucket không private, limits/MIME khác, quyền rộng hơn dự kiến hoặc policy rộng/permissive không tương ứng:

```sql
SELECT p.oid::regprocedure AS signature, p.prosecdef AS security_definer,
       has_function_privilege('anon', p.oid, 'EXECUTE') AS anon_exec,
       has_function_privilege('authenticated', p.oid, 'EXECUTE') AS authenticated_exec,
       pg_get_functiondef(p.oid) AS definition
FROM pg_proc p JOIN pg_namespace n ON n.oid=p.pronamespace
WHERE n.nspname IN ('private','public')
  AND p.proname IN ('prepare_upload','prepare_message_upload','phase_b_finalize_upload',
                    'c_lock','b_actor','require_identity','lock_profile','finalize_upload');

SELECT id, public, file_size_limit, allowed_mime_types
FROM storage.buckets
WHERE id IN ('profile-media','social-media','chat-media');

SELECT schemaname, tablename, policyname, permissive, roles, cmd, qual, with_check
FROM pg_policies
WHERE schemaname='storage' AND tablename='objects'
ORDER BY policyname;

SELECT to_regclass('supabase_migrations.schema_migrations') AS migration_ledger;
```
